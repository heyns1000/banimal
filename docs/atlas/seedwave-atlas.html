Preface

Before this, "the Banimal™ Connector" meant four different things depending on which conversation you caught — a freight dashboard, a WordPress plugin, a GitHub sweep, a device network. None of those were wrong. They were just unindexed.

This atlas exists to stop re-describing the ecosystem from memory. Every entry past this page was checked against an actual repository, an actual committed file, or an actual open pull request — not recalled, not assumed. Where something is a plan and not yet a fact, it's marked planned, not quietly promoted to real.

What this document is

This is the working index of the Banimal™ ecosystem — every system, worker, plugin, page, and repository that's real right now, listed against the one that's coming next. It reads like the documentation you'd expect from Cloudflare, Vercel, or GitHub: numbered entries, a status per row, a location you can go check yourself. The difference is that it's built around a hand-drawn brand instead of a company logo, and it answers to one master file instead of a style guide committee.

Two rules govern every row below. First, a system only earns a page number once it's been checked — read from the repository, not remembered from an earlier conversation. Second, status is honest: live means it's running in a real repository today; draft means it exists as a file but isn't committed anywhere that matters yet; planned means it doesn't exist at all yet and is named here so it isn't reinvented twice.

The finding that reshaped this atlas mid-build: a plugin literally named Banimal™ Ecosystem Connector already ships from this repo, v5.0.0, live. It isn't the brand-alignment layer this atlas is building toward — it's a signed WooCommerce↔Worker commerce bridge — but the name collision is real, and the fix is one plugin with two modules, not two plugins.
